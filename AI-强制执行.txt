========================================================================
补充说明：部署之外的约定与坑
========================================================================
这份文件写给正在操作这个目录的人（或 AI 代理），目的只有一个：
把已经确定过的事情写下来，省得每次都重新问一遍。

它是约定，不是命令。哪一条不适合你的场景，直接改。
========================================================================


一、动手之前，先看这三样
------------------------------------------------------------------------
  1. 本文件
  2. AI-OPERATOR.txt     完整部署步骤
  3. config.json         当前生效的配置

看完再动手。缺什么文件就去读代码和测试——大部分问题的答案在
test.js 和 rules.js 里，比描述更准。


二、默认行为（已经写进代码，改之前先确认这是你要的）
------------------------------------------------------------------------
  · 触发规则：阈值 10；普通消息攒 20 条整批判一次；
    @、叫名字、直接请求、呼叫词（且带当前人格名字）才立即回
  · 名字规则：彩蛋人格期间要用该人格自己的名字叫它，用默认名不理
  · 人格格式：人格文件里 requirePattern 声明的内容，回复必须带上；
    代码会检查、重试、兜底，不需要手动补
  · 识图：纯图不回；配文字或有上下文才看；单群冷却默认 20 秒（可配）；
    同一张图 90 秒内不重复识别；出现 3 次自动拉黑，之后永不回
  · 记忆：memory/<实例>/<群号>/memory.json，实例之间互不可见
  · 边界：只聊天、识图；开发/写代码类请求按既定话术拒绝；政治话题中性回避
  · 作息、公告、节流：按 config.json 执行

  想让机器人更活跃，改人格文件的 replyRate（它优先于全局 threshold），
  而不是把节流放宽——这两件事的效果完全不同。


三、几条建议不要做的事（都有代价）
------------------------------------------------------------------------
  1. 不要为了省事去掉政治过滤、能力边界、记忆防投毒、输出净化。
     这四样是刻意设计的安全边界，不是碍事的检查。

  2. 不要虚构版本号、测试结果、更新记录。
     CHANGELOG 里没写的，就是没验证过。没有就说没有。

  3. 不要把 config.json / persona.md / memory/ / 密钥提交到公开仓库。
     .gitignore 已经排掉了，但提交前扫一眼总没坏处。

  4. 遇到不会的，读文件比猜快。
     实在读不懂再问，问的时候说清楚卡在哪一步——这样对方也知道从哪讲起。


四、Windows 上已知的坑（都是实际踩过的）
------------------------------------------------------------------------
1. NapCat 控制台中文全是乱码（如「顙机鞕飨鍻」）
   原因：NapCat 输出 UTF-8，Windows 控制台按 GBK 解码。
   处理：启动前 chcp 65001，并设 PYTHONUTF8=1；
        守护不要解析管道输出，改成读日志文件（UTF-8）。
   危害：若守护靠日志关键字判断状态，乱码会导致误判为"没起来"。

2. daemon.vbs 报「缺少对象: 'fso'」（代码 800A01A8）
   原因：用了 fso 但没有 Set 创建，或创建写在第一次使用之后。
   处理：把 Set fso = CreateObject("Scripting.FileSystemObject")
        放到最前面；每个对象变量都要 Set。
   排查：用 cscript //nologo ops\daemon.vbs 运行，能看到行号。

3. get_login_info 无响应 → 守护反复重启 NapCat（死循环）
   原因排序：没扫码登录 > HTTP 端口没开/不对 > access token 不匹配。
   处理：先用浏览器或 curl 验证
        http://127.0.0.1:3000/get_login_info
        · 能返回 user_id：接口通，问题在守护判断逻辑
        · 超时/拒绝：NapCat 没开 HTTP 或没起来
        · 401：token 不对
   规则：登录失败不等于进程故障，不能触发重启。

4. 同一秒出现大量结构相同的日志
   可能是守护重复打印，也可能是机器人在刷屏（回复自己/重复处理）。
   处理：等日志能正常显示后，确认是"收到"还是"发送"；
        检查 isSelf 过滤、节流与去重。

5. 守护进程 ≠ 机器人进程
   守护只负责拉起/监控；bot.js 可以单独跑。
   关掉守护不会让机器人报错，只是失去自动重启。

6. 文件编码三处不一样，弄错会静默失败
   .ps1 要 UTF-8 带 BOM（PS 5.1 否则按 ANSI 读，中文全碎）
   .bat 要纯 ASCII 无 BOM（cmd 按 GBK 读批处理）
   自启 .vbs 要 UTF-16LE 带 BOM
   JSON 带 BOM 会让 JSON.parse 直接抛 Unexpected token


五、文档、代码、配置冲突时
------------------------------------------------------------------------
  1. 代码的实际行为 > 文档描述
     文档写错了就去改文档，不要照着错的文档调参。

  2. 配置文件 > 人格文件 > 临时改动
     临时改动要落进文件，否则重启就没了。

  3. 用户明确说要改某个值时，直接改并说明后果。
     有疑虑可以讲一次，讲完按对方的意思做。

  4. 文档与代码不一致时，以代码为准，顺手把文档改对。


六、能自动做的，和必须人做的
------------------------------------------------------------------------
  可以自己做：
    装环境、装协议端、跑测试、改配置、重启、看日志、读报错、修小问题

  需要人来：
    QQ 扫码登录、提供 API key、决定要不要发到某个群

  每次改动后跑一次 npm test，确认没崩，再说改了什么、影响什么。


七、几个常见的返工原因
------------------------------------------------------------------------
  · 没跑测试就宣布"改好了"
  · 照着过期文档调参（先对一下代码）
  · 把"应该能行"当成"验证过"
  · 为了让机器人更活跃去放宽节流
